A vision-language-action (VLA) model maps perception and instruction
directly to low-level control, in one policy trained end-to-end. This is
an elegant architecture, but it inherits imitation learning's oldest
bottleneck: the policy only knows what its demonstration data covers,
and paired vision-action robot trajectories are expensive to collect at
the scale a general-purpose manipulator needs. An LLM or VLM, by
contrast, is pretrained on a far broader, cheaper-to-collect corpus,
text, code, and image-text pairs at internet scale, and already knows a
great deal relevant to manipulation, object affordances, spatial and
arithmetic reasoning, ordering and precondition logic, none of it
robot-specific, all of it transferable through code rather than a
demonstration dataset~\cite{liang2023codeaspolicies, huang2023voxposer,
huang2022innermonologue, singh2023progprompt}. This is the architectural
bet a decoupled Sense-Plan-Act pipeline makes: let the model plan in
language, and a separate execution layer turn that plan into motion.

The bet has a cost. A decoupled pipeline has to ask the model, somewhere,
to commit to numbers, a release height, a grasp width, a target
position, and nothing in an LLM or VLM's pretraining grounds those
numbers in the physical world it now acts in. Simulated validation hides
this cost almost entirely: an object's height, its grasp width, and the
distance a gripper must travel to release it safely are never actually
\emph{measured} there, they are asserted, correctly, by
construction~\cite{favaliRAS, rohmer2013coppeliasim, todorov2012mujoco}.
On real hardware none of these quantities are given; they have to be
computed, from noisy depth, an imperfect camera, or a hand-authored
scene file that may not match the physical table it describes.

We present a real-hardware ROS2 harness built around this architectural
choice (\S\ref{sec:harness}): a modular Sense-Plan-Act pipeline
supporting six reasoning strategies over two grounding modalities (a
static-scene LLM planner and a camera-grounded VLM planner), a small
library of parameterized manipulation skills, and a deterministic
code-grounding layer that overrides model-computed geometry with a
sensor- or action-derived value wherever the two could disagree. A
companion framework from the same group, RoboReason
Lab~\cite{favaliRoboReasonLab}, implements the same class of reasoning
strategies over the same kind of pipeline, but entirely inside
CoppeliaSim; ours, as far as we are aware, is the first version of it run
on a real manipulator.

Building and operating this harness on a real UR5cb manipulator surfaced
the cost concretely. Over six development sessions we found a recurring
pattern: whenever a planning prompt asked the model to compute a piece
of manipulation geometry itself, that computation was often wrong, in
ways that stayed silent until the arm dropped, crushed, or missed an
object. We diagnose six such bugs from production hardware logs
(\S\ref{sec:taxonomy}) and close five with the harness's code-grounding
layer, which computes the same quantities deterministically instead of
trusting the model's own arithmetic (\S\ref{sec:grounding-layer}). The
sixth, a multi-object placement collision, we diagnose but have not
closed; it turns out to be the dominant one, a 120-trial benchmark
(\S\ref{sec:evaluation}) shows it as the residual failure once the other
five are fixed, in \emph{both} the LLM and VLM pipelines regardless of
which grounded the scene. We read this taxonomy as a discovered
validation of the harness's design premise, not this paper's main
contribution: an LLM/VLM harness needs code-grounding precisely because
real deployment keeps asking the model to compute quantities only a
sensor, or an already-committed action, should determine.

The contributions of this paper are threefold:
\begin{itemize}[nosep]
  \item A real-hardware ROS2 harness for decoupled LLM/VLM manipulation
    planning, with a code-grounding layer as an explicit architectural
    component, presented as the real-hardware counterpart to
    simulation-only frameworks for the same class of reasoning strategies
    (\S\ref{sec:harness}).
  \item A taxonomy of six recurring geometry-grounding bugs, discovered
    while operating the harness on a real manipulator across six
    development sessions, five of which the code-grounding layer closes
    (\S\ref{sec:taxonomy}, \S\ref{sec:grounding-layer}).
  \item A 120-trial real-hardware benchmark, methodologically anchored to
    a directly comparable symbolic-simulation study~\cite{favaliRAS} and
    using a single unified model for both grounding modalities, showing
    that the sixth, still-open bug, multi-object placement collision, is
    the dominant residual failure in \emph{both} arms, and what that
    implies for evaluating LLM/VLM robot harnesses before hardware
    deployment (\S\ref{sec:evaluation}).
\end{itemize}
