\subsection{Design principle}

\rev{Every bug in Table~\ref{tab:taxonomy} is an instance of the same
mistake: the model is trusted for a computation that a sensor
measurement or an already-committed action in the plan could instead
answer exactly.} The fix for five of the six bugs follows
the same rule: \emph{pull geometric arithmetic out of the model and into
code wherever the answer is computable from a sensor measurement or a
paired action already in the plan, leaving the model responsible only
for the symbolic decision of what to do and where, not how much}. The
model still chooses which object to pick and which zone to release
into; a deterministic post-processing layer overwrites the specific
numeric fields most exposed to \S\ref{sec:taxonomy}'s failure modes,
using only information already available at plan time. The sixth bug
(Case 6, \S\ref{sec:case-collision}) is not a scalar this rule can
overwrite, since it is a trajectory-level, time-dependent contact
problem, and is addressed separately, and only partially, below.
\rev{The layer implements this rule as a small set of deterministic
correction functions, applied to the plan before execution; the first
pair closes Case 1.}

\subsection{Object and release height}
\label{sec:fix-height}

\rev{\code{fix\_object\_height} and \code{fix\_release\_height} are
these two functions.} Given a generated plan, \code{fix\_object\_height}
recomputes every release step's \code{object\_height} as the true
vertical distance from the paired pick's actual grasp contact point to
the table surface, $\height - \descent$ in the notation of
\S\ref{sec:case-grasp-mismatch}, rather than accepting whatever height
value the model reported. This directly closes Case 1: the release-lift
amount is now derived from the \emph{same} descent the executor
actually commanded during the pick, which by construction cannot
disagree with itself, instead of from a separate,
independently-computed model output that could.

\code{fix\_release\_height} performs the analogous correction for the
release \emph{position}. Matching a release against the scene's
registered targets is done by \textbf{footprint containment}
($\text{position} \pm \text{size}/2$) rather than point-distance to a
target's center, since Case 3 showed point-distance matching misses
valid placements inside a target zone tens of centimeters wide. A
release position that \emph{exactly echoes} a target's or object's own
registered coordinates is treated as intentional and left untouched,
while one that merely \emph{drifted} into a zone's footprint is nudged
back outside along whichever axis needs the smaller correction, and only
when that zone's surface sits meaningfully above the bare table, since
nudging away from the near-table-height generic ``table'' zone would
otherwise push objects off the table's edge escaping a zone that
legitimately contains most of the workspace.

\subsection{Width-aware TCP offset}

Because the gripper's fingers pivot, the flange-to-contact distance for
a given commanded width is not constant. We measure this at three
representative widths (fully closed, mid-open, fully open) and
interpolate piecewise-linearly between them at plan time, setting the
executor's tool transform per-pick from the plan's reported grasp width
and resetting it to a default afterward. Pick descent is additionally
capped at (calibrated offset $-$ clamp clearance), so tall objects are
gripped nearer their top rather than driving the gripper's rigid
mounting body into them. This closes Case 5.

\subsection{Zone-aware spacing: a partial mitigation for Case 6}
\label{sec:zone-spacing}

For a target zone that receives multiple releases in one plan, we lay
out occupants on a grid centered on the zone's anchor and clamped to its
registered bounds, falling back to an unbounded grid only when no known
zone matches. This closes the \emph{static} half of Case 6: final
release positions no longer overlap or overflow a zone smaller than the
model's own unclamped guess would have. It does not close the
\emph{dynamic} half: the arm's approach trajectory to the $n$-th release
is not checked against the already-placed $(n-1)$-th object's footprint,
nor is a released object's small residual motion constrained at all.
\S\ref{sec:evaluation} reports this as still the dominant failure mode;
\S\ref{sec:discussion} returns to what closing it would require.

\subsection{Best-effort grasp-width sampling}

For the VLM pipeline, grasp width is estimated by deprojecting a
detected bounding box's left and right edge pixels. Sampling directly on
the object's silhouette boundary is the single worst location for valid
depth, since boundary pixels are the most exposed to occlusion and
parallax error, and a single failed sample previously aborted the
entire batched deprojection call over a parameter, grasp width, that
does not even affect whether \emph{pick} and \emph{release} themselves
are safe. We fixed this by sampling slightly inset from the raw
silhouette edge instead of on it, and by isolating width estimation
into its own best-effort call that degrades to the model's own guess on
failure instead of aborting the plan. This closes Case 4 without
requiring width to be depth-verified in every case, an open limitation
we return to in \S\ref{sec:discussion}.

\subsection{Validation}
\label{sec:validation}

Each fix in this section was developed and iterated against real,
previously-failing production runs: the per-run debug artifacts our
system records for every planning call (raw model response, active
configuration, and, in VLM modes, the captured camera frame) let us
replay the exact inputs that produced a given hardware failure and
confirm that the corrected pipeline now produces the hand-derived
expected geometry for that same input, rather than validating only
against synthetic test cases. This retrospective replay, together with a
unit-level regression suite (45/45 passing across all reasoning-method
implementations at the time of writing), gives us confidence that each
fix addresses its diagnosed root cause. \S\ref{sec:evaluation} reports
the residual failure distribution with the harness's code-grounding
layer in place.
